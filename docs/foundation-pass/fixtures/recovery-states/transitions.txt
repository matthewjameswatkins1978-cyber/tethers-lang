# Recovery State Transitions
# Source: src/replay_windows.rs (ledger tests 01-30)

## Ledger Generations

| Generation | Valid Transitions | Terminal? |
|---|---|---|
| 0 (claim_only) | -> 1 (armed) via publication | No |
| 1 (armed) | -> 2 (succeeded/failed/uncertain) via execution | No |
| 2 (succeeded/failed/uncertain) | None | Yes (permanent) |
| 3+ | Rejected on creation | Yes (invalid) |

## Recovery Contract

- Generation 0 can always be reconstructed (idempotent claim).
- Generation 1 requires gen-0 predecessor; mismatch fails closed.
- Generation 2 requires gen-1 predecessor; mismatch fails closed.
- Sibling actions have distinct logical keys; claims don't cross-contaminate.
- Lock acquisition faults, publication faults, and binding mismatches all fail closed.
- Orphan chains fail whole ledger closed (no partial recovery).
- Malformed claim digests fail closed regardless of generation position.
- Restart never generates new UUID for an existing logical tuple.
