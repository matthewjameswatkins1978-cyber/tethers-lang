## Requested outcome

Expose the existing Tethers M3 conformance machinery through a new public CLI
command `plug conform`. The command must run provider code only with an explicit
`--allow-non-isolated-supervised-execution` approval flag, use an ephemeral
workspace with exact-candidate trust, and leave no durable state behind.

## Changes made

- `src/cli.rs` — Added `Conform` variant to `PlugCommand` with `--package`
  (absolute path) and `--allow-non-isolated-supervised-execution` flag. Added
  strict CLI syntax test `p2b_plug_conform_syntax_is_strict`.

- `src/plug_conform.rs` — New module (371 lines). Implements the full public
  conform pipeline:
  1. Absolute package path validation
  2. Approval gate: absent flag returns `approval_required` / exit 5
  3. Ephemeral workspace creation in system temp with a unique UUID
  4. Candidate preparation via `prepare_installation_candidate`
  5. Exact-candidate trust via `ExactCandidateTrustStore` + inline
     `InstallationRequest` with authority label `tethers-public-conform-cli`
  6. Supervised launch preparation via `PreparedSupervisedLaunch::prepare`
     with 30s wall-time limit
  7. Conformance execution via `run_host_conformance_with_authority`
  8. Clean scratch directory after conformance
  9. Clean workspace on exit
  10. Public success/failure mapping with full conformance evidence

- `src/application.rs` — Added routing arm for `PlugCommand::Conform` to
  `plug_conform::run_conform`.

- `src/lib.rs` — Declared `pub mod plug_conform`.

- `tests/p2b_plug_conform_cli.rs` — New integration test (13 tests) proving
  the public route against real host + fixture provider binaries.

## Decisions and assumptions

- No second conformance engine. `run_host_conformance_with_authority` is
  reused directly with an ephemeral `ExactCandidateTrustAuthority`.
- The existing `SUPERVISED_PROFILE_LIMITATION` constant is used verbatim to
  report non-isolation in the public output. No new profile vocabulary.
- Public V1 wall-time constant: 30 seconds.
- Trust uses authority label `tethers-public-conform-cli`.
- The ephemeral workspace is removed on both success and failure. If removal
  fails, the result is still reported (cleanup is best-effort for the
  workspace, but the note records this as a design decision).
- No dependencies changed. `Cargo.toml` and `Cargo.lock` are untouched.

## Discoveries

- `ExactCandidateTrustStore::create` requires an `InstallationRequest` with
  `ExactCandidate` scope, `Disabled` target state, and
  `allow_non_isolated_supervised_execution: true`. These are constructed
  inline rather than loaded from a file for the ephemeral authoring trust
  path.
- The conformance engine always returns `Ok(ConformanceEvidence)` even on
  internal failures — the error case is recorded as a `conformance_session`
  failure case entry with a `safe_diagnostic_code`.

## Remaining risks

- Cleanup of the ephemeral workspace is best-effort. If `remove_dir_all` fails,
  the result is still returned but a small temp directory may persist.
- The 30-second wall-time limit is a V1 constant. Later work may expose
  resource-limit tuning.
- No known risks within packet scope.
