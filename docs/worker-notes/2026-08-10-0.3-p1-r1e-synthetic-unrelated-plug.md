## Discoveries

- The `m3_fixture_provider` binary is the only test binary that can serve as a synthetic provider payload for conformance. Its identity (`tethers-stdio-fixture`) and tool name (`fixture_ping`) are hard-coded and must match the package manifest.
- Without a real executable provider binary, the conformance layer (`run_host_conformance`) fails at `CreateProcessW`. This is a genuine architectural constraint: package installation requires a real provider executable for conformance.
- `fs::canonicalize()` on Windows returns `\\?\`-prefixed paths when the input is a `PathBuf` from `std::env::temp_dir()`, but returns non-prefixed paths when given a plain string path. Tests normalize both sides for comparison.
- The generic machinery continues to handle new Plug identity + scope shape without any production-side knowledge, as expected.
