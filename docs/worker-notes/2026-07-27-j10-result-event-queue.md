## Requested outcome

After one evaluation finishes and creates a standard Result Anchor, place that
Anchor at the end of a host-owned FIFO queue. The host then evaluates queued
Result Anchors one at a time in FIFO order, without recursion, parallelism, or
retry. A Result Anchor generated by a queued evaluation is appended to the tail.

## Design

### Queue module (`event_queue.rs`)

- `ResultEventQueue` wrapping `VecDeque<ResultAnchor>`.
- Narrow operations: `enqueue`, `pop_front`, `is_empty`, `len`.
- Internal `VecDeque` not exposed.

### Causal context (`InputEventContext`)

- `event_id`, `correlation_id`, `generation`.
- Initial external event: all from request event ID, generation 0.
- Generated Result Anchor: from the anchor's fields.

### Result Anchor causality

- `ResultAnchor::new` updated to accept `correlation_id`, `causation_id`,
  `generation` explicitly.
- Initial action result: correlation = root event, causation = root event,
  generation = 1.
- Result from a queued evaluation: correlation = root, causation = parent
  anchor event ID, generation = parent generation + 1.
- Checked addition for generation; overflow fails closed.

### Queueing writer

- `QueueingResultAnchorWriter` composes the existing response writer with the
  queue.
- Writes the anchor into the response, then enqueues the same typed anchor.
- Returns success only when both succeed.
- Test-only failing writer preserves the ability to prove that a failed write
  enqueues nothing.

### Follow-up request construction

- `build_follow_up_request` starts from a pristine copy of the original request
  template.
- Replaces event with the Result Anchor's event_id, event_name, and serialized
  Facts object (direct, not wrapped).
- Replaces top-level external `facts` with `{}`.
- Preserves protocol_version, language_version, tether source, capabilities.

### Follow-up evaluation ID

- `eval_followup_<lowercase SHA-256 hex of UTF-8 event_id>`.
- Deterministic, fixed length, no raw payload included.

### Outer coordinator

- `process_one_event` processes one event completely and may append to the
  queue.
- Outer loop drains the queue with no recursion.
- `follow_up_evaluations` added to initial output when at least one queued
  event was evaluated.
