## Behavioural Result

The `OperationalScope` enum (with FileTools/Pdf variants) is replaced by a generic `OperationalScopeEvidence` struct. The generic lifecycle no longer contains any plug-subject-specific branching or constants. A new Plug with a new operational-scope shape can now be enabled and launched without editing Tethers core.

### Scope evidence model
- Carries: schema_version, installed_identity, package_identity, provider_identity, scope_schema_digest, canonical_scope_json (JCS), authority, integrity_digest
- Deterministic SHA-256 integrity over canonicalised covered fields
- Tamper detection on validate(): recomputes digest from stored fields and checks round-trip of canonical_scope_json through JCS

### Generic enable flow
- Scope file envelope: `{"schema": "tethers.plug-scope/1", "scope": {...}}`
- Scope schema read from installed plug's plug.json (`provider.operational_scope_schema`)
- Schema digest computed from canonicalised schema JSON
- `OperationalScopeEvidence::create()` validates, canonicalises, and digests the scope

### Generic launch delivery
- `TETHERS_OPERATIONAL_SCOPE_JSON` env var with canonical scope JSON
- `TETHERS_OPERATIONAL_SCOPE_DIGEST` env var with integrity digest
- No `__TETHERS_*` placeholder substitution in launch args
- No `TETHERS_PDF_*` or `TETHERS_FILE_*` env vars

### Reference provider migration
- PDF Tools provider: reads scope from `TETHERS_OPERATIONAL_SCOPE_JSON` instead of `--query-root` arg and `TETHERS_PDF_*` env vars
- File Tools provider: reads scope from `TETHERS_OPERATIONAL_SCOPE_JSON` instead of `--query-root`/`--source-root`/`--destination-root` args
- Internal `PdfOperationalScopeBinding` and `file_tools::OperationalScopeBinding` retain validation but add `from_canonical_scope_json()` parse methods

## Discoveries

1. The `Provider` struct in `package.rs` uses `#[serde(deny_unknown_fields)]`, requiring explicit addition of `operational_scope_schema` field. Added as `Option<serde_json::Value>` with `#[serde(default)]` for backward compatibility with packages that don't declare a schema.

2. The conformance test suite (`j23c2_pdf_conformance.rs`) tests the removed `__TETHERS_PDF_*` placeholder protocol directly. The task packet explicitly defers conformance redesign to P2 ("Do not redesign generic conformance in this packet"). Two tests fail on the removed placeholder expectations — this is architecturally correct but requires P2 to address.

3. `x-tethers-path: "canonical-directory"` support in the scope validation pipeline is not yet implemented. The schema is declared in plug.json and its digest is available, but the actual validation of `x-tethers-path` during enablement is deferred.

4. The synthetic plug test (`example.text-inspector`) is not yet added. The architecture supports it — the scope model is fully generic — but the focused test needs to be written.

5. `scope_request_invalid` error code strings still contain hardcoded PDF test fixtures in `j24d_plug_enable_scope_file.rs`. The enable command itself is generic, but scope file tests use PDF-specific fixture values.

## Remaining Risks

1. **Conformance redesign (P2)**: The 2 failing conformance tests test the removed `__TETHERS_*` placeholder behavior. P2 must implement generic conformance without the current fixture-based assumptions.

2. **x-tethers-path canonicalisation**: The canonical-directory path validation (`x-tethers-path: "canonical-directory"`) declared in the scope schemas is not yet enforced during scope validation. Hostile paths could bypass canonicalisation until this is implemented.

3. **Synthetic plug proof**: The `example.text-inspector` synthetic plug test proving zero core changes for a new plug is not yet written. The architecture supports it but evidence is missing.

4. **Pre-0.3 enablement state migration**: Existing enablement records serialized with the old `OperationalScope` enum will fail deserialization. The task authorizes migration but does not provide an automatic migration utility.
