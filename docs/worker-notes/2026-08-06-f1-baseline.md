3. Exit code convention: CLI uses exit code 2 for invalid usage, 0 for success.
4. OCaml engine has no direct tests: all testing via Rust host or PowerShell scripts.
5. No `.mli` files: OCaml modules expose full internals.
6. `application.rs` at 8,260 lines: largest file, mixed concerns.
7. No store has confirmed directory-entry durability: the Replay Ledger calls `FlushFileBuffers` after rename on the renamed file handle and verifies content by reopen-and-compare, but the parent directory entry is not explicitly flushed. All other stores lack even file-handle-level post-rename durability.
8. Trail uses append+sync, not write-then-rename. No per-line digest or integrity footer.
9. `m3_store.rs` (StoreRoot) is shared persistence layer for 7 stores.
10. Local Anchor Admission Store lacks `verify_chain()` on its store root.
