## C1C correction bookkeeping

The C1 phase explicitly excluded host scheduling changes. That narrowing was
not authorised by Lucy's original packet: the C1 mission required the
reference runtime to respect the semantic group boundary (attempt every group
member, join after all members reach terminal outcomes, block later Actions on
a non-success join). This correction restores and completes the originally
required host execution / join semantics. It is a scope correction, not a
re-implementation: the planner foundation is unchanged and no OCaml code was
modified.

## Requested outcome

Make the reference host respect the C1 semantic group boundary: once execution
of an authorised `together` group begins, every member is attempted once
regardless of whether an earlier sibling fails; only after every member reaches
a terminal outcome does the group join; a successful join permits later
Actions, any other outcome blocks them. Serial execution remains the valid C1
reference schedule — no physical parallelism — but serial behaviour must match
what a future genuinely concurrent runtime would observe: failure stops at the
join, not inside the fan-out.

## Decisions and assumptions

- Serial is a valid C1 schedule: group members run serially in source order,
  but the semantic boundary (every member attempted, join after terminal
  outcomes, non-success join blocks later items) matches a future genuinely
  concurrent runtime.
- Member success for the join = Completed or Replay(BlockedCompletedSuccess);
  everything else (Failed, Uncertain, Denied, Unattempted, AuditFailed, other
  replay states, approval-required) is non-success. The aggregate for a
  non-success group is the first non-success member's result in source order,
  preserving every outcome distinction — `uncertain` is never flattened into
  failure.
- Malformed group metadata fails closed with `InvalidData` before any
  dispatch; it is never silently reinterpreted as sequential execution.
- Authorisation remains per Action; no group-level permissions are created;
  a Plan remains a request, not permission. The legacy `__legacy` route and
  the installed-adapter seams stay single-Action and fail closed explicitly
  for larger plans via `extract_single_action`.
- No group-wide idempotency keys; per-Action replay identity material is
  unchanged; each member gets its own replay claim and `execution_id`.
- The join evidence is one additive durable `GroupJoinEntry` (smallest generic
  `Trail` extension) plus one presentation `group_joined` entry; the planner
  `group_planned` evidence is retained.
- The C1C TB tests provision a native-Windows replay root (ACL hardening via
  pwsh + `provision_replay`), the same pattern the m4 production evidence
  fixtures use, because the J09 ledger requires an exactly-provisioned,
  exactly-DACL'd root.

### Defect

Lucy's review of the pushed C1C result found one bounded acceptance defect in
`host_execution.rs::dispatch_matched_plan`:

```rust
let groups = plan
    .get("groups")
    .and_then(Value::as_array)
    .map(Vec::as_slice);
```

`and_then(Value::as_array)` silently mapped a PRESENT but non-array
`plan.groups` value to `None`, making malformed top-level group metadata
indistinguishable from an absent optional field and allowing sequential
execution.  The frozen rule being repaired: never silently reinterpret invalid
group metadata as sequential execution.

### Correction

The top-level decode in `dispatch_matched_plan` now distinguishes three cases
explicitly:

- absent `plan.groups` → `None` → ordinary sequential plan (unchanged);
- present JSON array → passed to `build_plan_schedule` unchanged (unchanged);
- present any-other value (null / object / string / number / bool) →
  `ExecutionServiceResult::InvalidData { message: "plan.groups was not an array" }`
  before any Action dispatch.

No change to `build_plan_schedule`, group execution semantics, OCaml,
dependencies, toolchain, Cargo.lock, or any other C1C behaviour.

### Changes made

- `tethers-0.1/host-rust/src/host_execution.rs` — `dispatch_matched_plan`
  top-level `plan.groups` decode (the correction); new focused production-route
  regression `c1c1_present_non_array_plan_groups_fails_closed_before_dispatch`
  and its runtime-fixture helpers (`c1c1_test_manifest`,
  `prepared_runtime_for_c1c1`, `c1c1_matched_response`, `c1c1_actions`).

The regression drives the real production route: `dispatch_matched_plan` on a
real `HostExecutionService` backed by a real `PreparedRuntime` (config + tether
+ manifest on disk, the established `prepare_runtime` pattern).  It asserts for
each of null / object / string / number / bool that the result is
`InvalidData` containing `plan.groups` AND that no Trail file was created.
`FileTrail::open` is the last gate before `execute_plan` /
`execute_one_action`, so a missing trail file proves zero executor or provider
activity.  Positive controls prove absent groups and a present valid array both
proceed to Trail open (dispatch begins) and are never rejected as malformed.
