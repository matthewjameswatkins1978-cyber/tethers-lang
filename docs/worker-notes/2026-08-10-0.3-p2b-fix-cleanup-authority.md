## Requested outcome

The original P2B implementation passed functional verification but Lucy
rejected acceptance because:
1. Cleanup failures were silently discarded via `.ok()` and `let _ = fs::remove_dir_all(...)`.
2. The task packet remained stale from P1-R1G-RERUN.

This fix makes cleanup failures authoritative, updates the task packet, and
reconciles the three previously-unrun required commands.

## Changes made

- `src/plug_conform.rs` — production change:
  - `cleanup_workspace` returns `Result<(), String>` instead of silently discarding errors.
  - `run_conform_in_workspace` returns `(PlugCommandResult, bool)` where the bool is scratch-cleanup-failed.
  - `prepared_launch.cleanup_scratch().ok()` replaced with `.is_err()` capture.
  - `run_conform` always attempts workspace cleanup regardless of conformance outcome or scratch cleanup failure.
  - If either scratch or workspace cleanup fails, overrides the conformance result with `conformance_cleanup_failed` / `Failed` / exit 6.
  - Added `#[cfg(test)] fn finalise_conform_result` test seam.
  - Added `mod tests` with 6 focused unit tests.

- `docs/CURRENT_CLINE_TASK.md` — replaced stale P1-R1G-RERUN packet with P2B-FIX task.

- `docs/worker-notes/2026-08-10-0.3-p2b-fix-cleanup-authority.md` — new.

## Decisions and assumptions

- Cleanup failure always takes precedence over a successful conformance result.
  This follows the packet directive and the principle that ephemeral state
  persistence is the stronger host-integrity problem.
- The safe public message "ephemeral conform state could not be completely
  removed" contains no path, temp directory name, or raw filesystem error.
- Cleanup of the scratch directory is attempted even when conformance fails
  or is interrupted; then full workspace cleanup is always attempted.
- The test seam `finalise_conform_result` is `#[cfg(test)]` only, not exposed
  in production builds.
